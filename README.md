## Содержимое

В базе ровно одна категория: `fptn-blacklist` (в protobuf сохранена именно в нижнем регистре). Каждая запись имеет тип RootDomain: совпадают сам домен и его поддомены. Все уникальные домены сохраняются, включая поддомены, даже если их уже покрывает родительский домен. Сборщик использует официальную protobuf-схему V2Fly, затем проверяет декодирование, имя категории и количество записей.

Это список для маршрутизации, а не самостоятельное указание блокировать трафик. Действие определяет конфигурация клиента.

## Автоматизация

- Ежедневная проверка в 02:17 UTC / 05:17 МСК.
- SHA-256 скачанного исходника сравнивается с последним опубликованным релизом FPTN.
- Без изменений сборка и публикация пропускаются.
- Первый push и изменения сборщика/workflow принудительно создают сборку.
- Ручной запуск: Actions → Build geosite → Run workflow. При неизменном исходнике он также пропускает сборку.
- Сохраняются текущая версия и 10 предыдущих: максимум 11 опубликованных релизов с префиксом fptn-.
- После публикации удаляются более старые релизы FPTN вместе с их тегами. Другие релизы не затрагиваются.
- Ошибки скачивания, проверки и сборки не изменяют опубликованную рабочую версию.
- Публикация сначала создаёт черновик со всеми файлами. Неудачная публикация может оставить черновик; такие черновики не считаются рабочими версиями и удаляются вручную.

В каждом релизе: geosite.dat, geosite.dat.sha256, russia.txt, source.sha256, domains.txt, build-info.json, go.mod и go.sum. Последние два файла фиксируют зависимости конкретной сборки. Зависимости разрешаются заново только при сборке; обновление зависимостей само по себе не запускает выпуск.

Для публикации достаточно штатного GITHUB_TOKEN с contents: write; дополнительные секреты не нужны. Политика организации/репозитория должна разрешать GitHub Actions и запись в содержимое репозитория.

Расписание работает из основной ветки. GitHub может задерживать запуски; в публичном репозитории после 60 дней без активности расписание может быть отключено GitHub, даже если проверки выполнялись. Проверяйте состояние Actions периодически.
